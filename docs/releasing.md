# Releasing

Releases are cut manually from `main` by a GitHub Actions workflow; GoReleaser builds and publishes the artifacts.

1. GitHub -> Actions -> **Release** -> **Run workflow**, branch `main` (other refs are rejected).
2. Type the version with a `v` prefix: `v0.1.0`, or `v0.2.0-rc.1` for a pre-release (published as a GitHub pre-release automatically).
3. The `test` job checks the ref, validates the version (semver, valid tag name, tag not yet on the remote), then runs the secret check, `go vet` and `go test -race ./...`.
4. The `release` job (the only one with `contents: write`) creates an annotated tag as `github-actions[bot]`, pushes it and runs `goreleaser release --clean`. Release notes are generated by GitHub.

Only one release runs at a time. Releases are published non-draft, so a failure after the tag push needs manual cleanup (the workflow prints the commands):

```sh
gh release delete <version> --yes        # only if the GitHub Release was created
git push origin :refs/tags/<version>     # delete the remote tag
```

## Artifacts

For `linux` and `darwin` on `amd64` and `arm64`: `garmin-papi-mcp_<version>_<os>_<arch>.tar.gz` (static binary built with `CGO_ENABLED=0 -trimpath`, version injected via `-X main.version`; `README.md`, `LICENSE`, `docs/*.md`, and `deploy/*`) and `checksums.txt` (sha256). `<version>` in file names has no `v` prefix.

```sh
sha256sum --ignore-missing -c checksums.txt     # Linux
shasum -a 256 --ignore-missing -c checksums.txt # macOS
```

The `ldflags` in `.goreleaser.yaml` mirror the Makefile's. Build locally with `make build` or `goreleaser release --snapshot --clean --skip=publish`.

All actions and the GoReleaser version are pinned (actions to full commit SHAs); bump them by hand.
